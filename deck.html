1 · Understand the situation

The text is in there. It's just not reachable.

Who

  • Ops / back-office analyst — opens a file, hunts for a figure
  • Legal & compliance — clause review, obligations
  • Risk / credit officer — cross-document checks
  • Downstream systems — need structured fields, not prose

What hurts today

  • Scanned pages are opaque: no search, no filter, no aggregation
  • Heterogeneous layouts, tables, stamps, multi-doc PDFs
  • Manual reading does not scale; errors are silent
  • No audit trail for "where did this number come from?"

What they actually ask

  • Lookup — "What is the IBAN on this contract?"
  • Aggregate — "Total charges across these 12 statements"
  • Compare — "Does the deed match the loan application?"
  • Infer — "Is there an early-repayment penalty?"
  • Act — "Flag this file for manual review"

Design consequence: four of those five question types cannot be answered by OCR alone.

Constraints we design around

  • Regulated sector: PII, EU data residency, retention limits
  • Every answer must be auditable and reconstructable
  • A wrong number is far more expensive than "I don't know"
  • Document volume is daily and batchy, not streaming

Assumptions we're making

  • Corpus is known in advance → we can pre-process
  • Scans are mostly machine-printed, ~200–300 dpi
  • A human review queue already exists to escalate into
  • We can call a hosted frontier VLM from inside the perimeter
2 · Design the capabilities

Six capabilities. Only three need generative AI.

C1 Ingest & normalize

Dedupe by hash, split multi-doc PDFs, deskew, orientation, quality score, page images. Deterministic + classic CV.

C2 Perceive the page

Layout-aware reading: text, reading order, tables, key-value regions, stamps, signatures — with bounding boxes. VLM + OCR cross-check.

C3 Classify & route

Document type + language → selects the extraction schema and the validation rules. Small classifier, rules first.

C4 Extract to schema

Per-type JSON schema, per-field confidence, per-field provenance (page + bbox). Generative, constrained output.

C5 Reason & answer

Plan the question, retrieve, re-read pixels if needed, synthesize with mandatory citations, or abstain. Agentic.

C6 Act & escalate

Propose a next step, open a review task, emit structured output to downstream systems. Whitelisted, logged tools.

3 · The one idea worth remembering

We never throw away the pixels.

Most document pipelines flatten a page to text and then reason over a lossy transcript. Every downstream error inherits that loss, and nothing can recover it.

Text-only pipeline

  • A merged table cell becomes a wrong number, silently
  • A stamp, a signature, a strike-through simply vanishes
  • "Which column was this under?" is unanswerable
  • Re-asking harder does not help — the evidence is gone

Our pipeline

  • Every extracted value keeps page + bounding box
  • Hard or low-confidence questions trigger a crop and re-read of that exact region with a stronger model
  • The user is shown the highlighted crop, not a claim about it
  • Resolution is a cost dial: cheap pass for everything, expensive pass only where it matters

This is what makes it visual intelligence rather than OCR with a chatbot stapled on.

3 · The seam

Where deterministic software ends, and AI begins.

Deterministic — boring on purpose

  • Orchestration, routing, retries, idempotency
  • Retrieval, filtering, access control (applied before retrieval, never after)
  • All arithmetic, totals and date math
  • Format & checksum validation: IBAN, NIF, dates, amounts
  • Confidence thresholding and escalation rules
  • Audit logging and trace capture

Model-driven — where ambiguity lives

  • Reading an unfamiliar layout
  • Mapping messy page content onto a clean schema
  • Interpreting a clause, inferring an answer from context
  • Planning which tool a question needs
  • Judging whether a drafted answer is actually grounded

Rule we hold ourselves to: if a rule can do it, a model must not. Cheaper, testable, and it cannot hallucinate.

4 · Trust & control

Evidence-first, or no answer at all.

The hard gate

  • Every claim carries doc + page + bbox
  • A verifier agent checks each claim against its cited span
  • No citation → the answer does not ship
  • Abstention is a success state, not a failure

How we measure

  • Groundedness and citation accuracy — primary gate
  • Correct-abstention rate on unanswerable questions
  • Field precision / recall / exact match; table structure (TEDS)
  • End-to-end task success, p95 latency, cost per doc & per query

Golden dataset

  • ~300 real documents across the two families
  • Field-level ground truth, labelled by ops
  • ~150 Q&A pairs — 20% deliberately unanswerable, 20% adversarial / near-miss
  • Replayed nightly as a canary; blocks release on regression

Fallback ladder

  • Low confidence → re-read the crop with a stronger model
  • Still low → answer partially, state what is missing
  • Still low → abstain and open a review task
  • Human gets the pre-highlighted crop, not the whole file

Drift detection

  • Confidence distribution and abstention-rate shift
  • Per-document OCR quality score trend
  • LLM-judge sampling on live traffic + user thumbs-down
  • Alert on new document layouts appearing in the mix

Observability

  • One trace per question: plan, docs retrieved, crops read, prompts, model versions, confidences, cost
  • Fully replayable → we can always reconstruct why
  • That trace is the compliance artifact

5 · From concept to MVP

What we'd actually build first.

MVP — the thin slice

  • Two document families, ~500 real documents
  • Ingestion → VLM read → 10–14 field schema → validators
  • Hybrid retrieval + grounded Q&A with citations and abstention
  • Evidence viewer: answer next to the highlighted crop
  • Eval harness + 150 golden Q&A wired into CI
  • Three agents only: orchestrator, extractor, verifier

Deliberately simplified

  • Read-only — L0 autonomy, no action execution
  • No fine-tuning, no custom models: hosted frontier VLM
  • Batch ingestion overnight, no streaming
  • Single tenant, one language pair, no handwriting
  • Buy the model, the vector store, the object store. Build the orchestration, the schemas, the eval and trust layer — that is the differentiator

Hypotheses to kill fast

  • H1 A frontier VLM on page images beats OCR+text-LLM on our layouts → 50-doc bake-off, day one
  • H2 Citations + visible abstention are what buy ops trust
  • H3 Real questions are mostly lookups → the cheap SQL path carries the volume
  • H4 Cost per document is acceptable at production volume

Biggest risk is not model capability — it is numeric precision under regulation. So we measure groundedness before we add features.

5 · Phase 2 & close

What earns phase two.

We evolve only if…

  • Groundedness ≥ 95% and zero ungrounded numerics on the golden set
  • Field accuracy beats the current manual baseline at lower cost per document
  • Ops actually prefer the abstention over a guess
  • Cost per query stays inside the envelope at real volume

Then we add

  • L2 action layer: propose, human confirms, fully logged
  • Cross-document reasoning over an entity graph
  • Feedback-driven active learning from the review queue
  • Distilled small model for the high-volume document types to cut unit cost
  • Multi-tenant isolation and broader language coverage
